2 Business Background and Purpose

Purchasing and plant teams need a single view of purchase orders whose agreed delivery date has passed but whose goods have not been fully received. Today, buyers use standard list displays (ME2L / ME2M / ME2N with the "to be delivered" scope). Those lists do not group overdue items by vendor, do not age them, and do not show the overdue value per vendor.

The report will list, for one company code, every purchase-order schedule line that is past its delivery date and still has quantity open. Results are grouped by vendor, with the days overdue, the open quantity, the open value and an aging bucket for each line. It supports:

  • Vendor expediting – which vendors to chase first, and for which POs.
  • Vendor performance reviews – how much is overdue and how old it is, by vendor.
  • Supply-risk escalation – open value at risk per plant and purchasing group.

3 Scope

3.1 In scope

  • Standard purchase orders (document category F) for the selected company code.
  • Line items that are not deleted and not flagged "delivery completed".
  • Schedule lines with a delivery date before the key date and an open quantity greater than zero.
  • A vendor summary and a line-level detail list, both in an interactive ALV grid.

3.2 Out of scope

  • Contracts (K), scheduling agreements (L) and RFQs (A). Scheduling agreements can be added in a later phase.
  • Purchase requisitions not yet converted to a PO.
  • Invoice and payment status (GR/IR, AP aging), and service-entry-sheet acceptance for service items (see Open Point OP-03).
  • Any change to documents. The report is read-only; it does not send dunning or expediting messages.

4 Definitions – What "Overdue" Means

A schedule line is overdue when ALL of the following are true:
  1. PO header: company code = selected company code, document category = F, header not deleted.
  2. PO item: not deleted, "delivery completed" indicator not set.
  3. Schedule line: delivery date < key date (default = today).
  4. Open quantity = scheduled quantity − quantity delivered > 0.
  5. Days overdue ≥ the minimum days entered on the selection screen (default 1).

7 Processing Logic

StepDescription
1Read PO headers (EKKO) for P_BUKRS, document category F and header not deleted, applying the vendor, purchasing organization, purchasing group, document type and PO number ranges. Stop with message "No purchase orders found" if nothing is found.
2Read the items (EKPO) of those POs where the deletion indicator is blank, "delivery completed" (ELIKZ) is blank, and the plant is in S_WERKS. Join with step 1 at database level to avoid large intermediate tables.
3Read the schedule lines (EKET) of those items where the delivery date is before P_KEYDT and in S_EINDT.
4For each schedule line, open quantity = EKET-MENGE − EKET-WEMNG. Drop lines with open quantity ≤ 0.
5Days overdue = P_KEYDT − EKET-EINDT. Skip lines with an initial or invalid delivery date. Drop lines below P_MINDAY.
6Open value = open quantity × EKPO-NETPR ÷ EKPO-PEINH. If PEINH = 0, set the value to 0 and set the "Price check" flag to X. Calculation errors must not end the report; the affected line is flagged instead.
7Aging bucket: 1–30, 31–60, 61–90, 90+ days. If P_MINDAY = 0, lines due exactly on the key date are excluded because the delivery date must be before the key date.
8Add the vendor name, city, country and block indicators (LFA1) and the purchasing group name (T024) through single set-based reads.
9Summary mode: total by vendor + currency – number of POs, number of overdue lines, total open value, value per aging bucket, oldest days overdue. Detail mode: one row per schedule line.
10Sort: summary by total open value descending within currency; detail by vendor, then days overdue descending, then PO / item / schedule line.
11Show the result in an ALV grid (§8). If no lines qualify, show the information message "No overdue purchase order lines found for the selection".

12 Reconciliation with Standard SAP

For any vendor, the overdue lines can be checked against the standard list display:

  • ME2L (by vendor) or ME2M (by material), selection parameter "WE101 – Open goods receipt", same company code / purchasing organization, delivery date to key date − 1.
  • Open quantity per schedule line must match "Still to be delivered" in the PO schedule-line overview (ME23N).
  • Differences can be expected only for items with delivery-completed set but quantity still open (excluded here by design) and for service items (OP-03).

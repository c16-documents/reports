3.2 Validation of Selection Criteria

1. Revision Status (REL): T352R-OBJNR → JEST check: STAT = I0002 (Released) with INACT ≠ 'X'. JEST confirmed: OBJNR (CHAR 22, DE: J_OBJNR), STAT (CHAR 5, DE: J_STATUS), INACT (CHAR 1, DE: J_INACT).

2. Age Threshold: T352R-REVED ≤ SY-DATUM − P_DAYS (default 60 days).

3. Notification Completion (NOCO): All linked notifications (DIWPS_RV_CR-NOTIFID, DE: QMNUM) must have JEST STAT = I0072. QMEL-OBJNR (DE: QMOBJNR) used for JEST lookup.

4. Order Closure (CLSD): All linked orders (DIWPS_RV_CR-ORDER_NO, DE: AUFNR) must have JEST STAT = I0046. AUFK-OBJNR (DE: J_OBJNR) used for JEST lookup.

5. If ANY notification or order is open → revision skipped with error message.

3.7 Processing Logic

STEP 1 — Data Selection:

SELECT REVNR, REVTY, REVBD, REVED, IWERK, VAPLZ, VAWRK, AUFNR, OBJNR FROM T352R WHERE matching selection criteria. Field types confirmed from live system: REVNR (CHAR 8, DE: REVNI), REVTY (CHAR 2, DE: DIWPS_REVTY_CORE), REVED (DATS 8, DE: REVED), IWERK (CHAR 4, DE: IWERK), AUFNR (CHAR 12, DE: NW_AUFNR), OBJNR (CHAR 22, DE: J_OBJNR).

STEP 2 — REL Status Validation:

For each revision, read JEST WHERE OBJNR = T352R-OBJNR AND INACT ≠ 'X'. Check STAT = I0002 (Released). Also verify REVED ≤ SY-DATUM − P_DAYS. Sample data confirmed: JEST records with STAT=I0002 and INACT='' exist in the system (e.g., OBJNR 'RV100000000006').

STEP 3 — Get Linked Objects:

Read DIWPS_RV_CR WHERE WPID = revision_number. Confirmed fields from live system: WPID (CHAR 8, DE: REVNI), NOTIFID (CHAR 12, DE: QMNUM), ORDER_NO (CHAR 12, DE: AUFNR). Table has 30 fields total including IWERK, QMART, ARCH_ORDER.

STEP 4 — Notification Status Check (NOCO):

For each NOTIFID: SELECT OBJNR FROM QMEL WHERE QMNUM = notification_number (QMEL-OBJNR DE: QMOBJNR). Then SELECT STAT FROM JEST WHERE OBJNR = QMEL-OBJNR AND INACT ≠ 'X'. Check STAT = I0072 (NOCO). If ANY notification is not NOCO → skip revision.

STEP 5 — Order Status Check (CLSD):

For each ORDER_NO: SELECT OBJNR FROM AUFK WHERE AUFNR = order_number (AUFK-OBJNR DE: J_OBJNR). Then SELECT STAT FROM JEST WHERE OBJNR = AUFK-OBJNR AND INACT ≠ 'X'. Check STAT = I0046 (CLSD). If ANY order is not CLSD → skip revision.

STEP 6 — Close Revision (CLSD):

CALL FUNCTION '/AXONEBX/GET_REV_CLOSE' EXPORTING I_REVNR = revision_number, I_WERKS = planning_plant. Evaluate return and log result.

STEP 7 — Network Closure Logic (TECO):

Read T352R-AUFNR (network, CHAR 12, DE: NW_AUFNR). Check if network is linked to other revisions via T325R. For each other revision (excluding current), verify JEST STAT = I0046 (CLSD). If ALL are CLSD:

CALL FUNCTION 'BAPI_BUS2002_SET_STATUS' EXPORTING NUMBER = network_number (TYPE BAPI_NETWORK_LIST-NETWORK), SET_SYSTEM_STATUS = 'I0045' (TECO). IMPORTING RETURN = ls_return (TYPE BAPIRETURN1: TYPE CHAR 1, ID CHAR 20, NUMBER NUMC 3, MESSAGE CHAR 220, MESSAGE_V1–V4 CHAR 50). Then CALL FUNCTION 'BAPI_TRANSACTION_COMMIT' EXPORTING WAIT = 'X'.

If revision has no linked network → log info: 'Revision XXXXX closed without network'.

STEP 8 — WBS Closure Logic (TECO):

Read AUFK-PSPEL (NUMC 8, DE: PS_PSP_ELE) for the WBS element. Check if WBS is linked to other networks via AUFK-PSPEL. For each other network (excluding current), verify JEST status for TECO (I0045). If ALL are TECO:

CALL FUNCTION 'BAPI_BUS2054_SET_STATUS' TABLES I_WBS_SYSTEM_STATUS (TYPE BAPI_WBS_MNT_SYSTEM_STATUS). IMPORTING RETURN = ls_return (TYPE BAPIRETURN1). Then CALL FUNCTION 'BAPI_TRANSACTION_COMMIT' EXPORTING WAIT = 'X'.

STEP 9 — Email Notification:

If WBS successfully set to TECO AND T352R-IWERK = 'ECE2': Read SO15 distribution list for EC FI email addresses. Send email using MO-0595 template via CL_BCS or SO_NEW_DOCUMENT_SEND_API1.

STEP 10 — Log Output:

Display all collected log entries as a tabular spool list with columns: Revision No | Network No | WBS Element | Action (CLSD/TECO) | Result (Success/Error/Info) | Message Text. Stored as spool in background execution.

3. Partial Processing: If revision close fails, do NOT attempt network or WBS closure for that revision.

5 Assumptions in Technical Design

1. All service orders are expected to be closed (CLSD) within 60 days from revision end date (configurable via P_DAYS parameter).

2. The BAPI /AXONEBX/GET_REV_CLOSE is a partner-provided BAPI from the AXONE extension and must be available in the target system.

3. The distribution list SO15 for EC FI must be maintained in the system before the email feature is activated.

4. The MO-0595 email template must be configured and available.

5. DIWPS_RV_CR table stores the revision-to-notification and revision-to-order linkages (confirmed on live system: WPID, NOTIFID, ORDER_NO fields exist with 30 fields total).

6. T325R stores revision-to-network assignment (not confirmed on connected ECC system — must be verified on target S/4HANA system).

7. BAPI_TRANSACTION_COMMIT with WAIT = 'X' is called after each successful status change for synchronous database commit.

8. ZZ_ESLOT_START and ZZ_ESLOT_END are custom append fields on T352R — their existence must be confirmed on the target system.

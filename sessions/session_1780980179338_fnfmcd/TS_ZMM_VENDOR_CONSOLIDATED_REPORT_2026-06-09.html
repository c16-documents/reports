2 Code Quality

This report is a consolidated vendor master data extraction program that retrieves vendor information from multiple SAP tables including LFA1, ADRC, ADR6, ADRCT, LFB1, LFM1, and custom tables (ZVENDOR_BLOCK, ZMM_VENDOR_MSME, ZMM_VENDOR_BEE). The program uses standard ABAP Open SQL with inline declarations (ABAP 7.40 syntax) and outputs via REUSE_ALV_GRID_DISPLAY.

3.2 Validation of Selection Criteria

The following validations are performed on selection criteria:

  1. Mutual Exclusivity Check: Only ONE of the five secondary fields (P_STATUS, P_BLACK, P_BEGRU, P_BEGRU1, P_BRSCH) can be selected at a time. If more than one is populated, error message "Please select only one input from last 5 secondary fields" is displayed.
  2. Default Account Groups: If all selection criteria are empty, the program automatically loads vendor account group values from TVARVC variant 'ZMM_VEND_ACC_GROUP'. If this variant is empty, error "No data available in ZMM_VEND_ACC_GROUP variant" is displayed.
  3. Status Translation: P_STATUS value '1' is translated to 'ACTIVE', value '2' to 'INACTIVE'.
  4. Boolean Translation: P_BLACK, P_BEGRU, P_BEGRU1, P_BRSCH values '1' translate to 'Yes', '2' to 'No'.

3.5 Technical Flow Diagram

Program Execution Flow:

  1. AT SELECTION-SCREEN OUTPUT: Populate listbox values for P_STATUS, P_BLACK, P_BEGRU, P_BEGRU1, P_BRSCH using VRM_SET_VALUES
  2. START-OF-SELECTION:
    • Validate mutual exclusivity of secondary parameters
    • Translate parameter values (1→ACTIVE, 2→INACTIVE, etc.)
    • If no selection criteria, load default account groups from TVARVC
  3. Data Retrieval:
    • SELECT from LFA1 (vendor master general)
    • SELECT from CVI_VEND_LINK → BUT000 → BUT050 (group vendor relationship)
    • SELECT from ADRC (address data)
    • SELECT from LFB1 (payment terms)
    • SELECT from LFM1 (purchasing data/currency)
    • SELECT from ADR6 (email addresses)
    • SELECT from ADRCT (address remarks)
    • SELECT from ZVENDOR_BLOCK (blacklist status)
    • SELECT from ZMM_VENDOR_MSME (MSME certificate)
    • SELECT from ZMM_VENDOR_BEE (BEE level)
  4. Data Assembly: Loop through LFA1 results and populate final output structure with data from all related tables
  5. Filtering: Apply secondary parameter filters (status, blacklist, auth group, industry sector)
  6. Output: Display results via REUSE_ALV_GRID_DISPLAY

3.7 Processing Logic

The program follows a modular data retrieval approach with the following key logic components:

Data Retrieval Sequence:

  1. Vendor Master (LFA1): Primary vendor data including vendor number, name, city, account group, creation date, status flags (SPERR, SPERM, SPERQ), and custom fields (PO_NONPOVENDOR, RISK_CODE, RISK_CATG, ZZEINVOICE)
  2. Group Vendor Resolution: CVI_VEND_LINK → BUT000 → BUT050 chain to resolve business partner relationships and group vendor assignments
  3. Address Data (ADRC): Country, street, supplements, postal code, region
  4. Payment Terms (LFB1): ZTERM field for payment conditions
  5. Currency (LFM1): WAERS field for purchase order currency
  6. Email (ADR6): SMTP_ADDR for vendor email address
  7. Remarks (ADRCT): REMARK field for Wipro SPOC ID
  8. Blacklist (ZVENDOR_BLOCK): VFLAG for blacklist status
  9. MSME (ZMM_VENDOR_MSME): MSME_CERT_NUM for MSME certificate number
  10. BEE Level (ZMM_VENDOR_BEE): BEE_LEVEL for BEE certification level

Status Determination Logic:

IF ls_lfa1-sperr = 'X' OR ls_lfa1-sperm = 'X' OR ls_lfa1-sperq IS NOT INITIAL.
  ls_final-status = 'INACTIVE'.
ELSE.
  ls_final-status = 'ACTIVE'.
ENDIF.

Blacklist Determination Logic:

READ TABLE lt_zvendor_block1 INTO DATA(ls_zvendor_block1) 
  WITH KEY lifnr = ls_lfa1-lifnr BINARY SEARCH.
IF sy-subrc = 0 AND ls_zvendor_block1-vflag = 'X'.
  ls_final-blacklisted = 'Yes'.
ELSE.
  ls_final-blacklisted = 'No'.
ENDIF.

5 Assumptions in Technical Design

  • TVARVC variant 'ZMM_VEND_ACC_GROUP' contains the valid vendor account groups for default selection
  • Custom tables ZVENDOR_BLOCK, ZMM_VENDOR_MSME, and ZMM_VENDOR_BEE exist and are maintained
  • Users have table-level authorization for all accessed tables
  • The CVI_VEND_LINK table is populated for vendor-to-business-partner synchronization
  • System is SAP ECC 7.40 or higher with support for inline declarations and NEW # constructor expressions

6 Open Issues in Technical Design

  • Missing Authorization Checks: No AUTHORITY-CHECK implemented for vendor data access
  • Code Quality Non-Compliance: Uses TABLES declarations, TYPE-POOLS, and REUSE_ALV_GRID_DISPLAY
  • No Message Class: Inline messages not maintainable or translatable
  • Performance: Multiple FOR ALL ENTRIES in sequential SELECTs may cause performance issues with large vendor master data
  • Code Structure: All logic in event blocks without FORM routines or local classes makes maintenance difficult

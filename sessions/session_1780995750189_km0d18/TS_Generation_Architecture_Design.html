8 Design Principles

Principle 1: Template-First

"The template defines what we extract, not the other way around. We don't perform exhaustive analysis — we extract exactly what each template field requires."

Principle 2: Read Edges, Search Middle

"For large programs, read HEAD (lines 1-250) and TAIL (ALV section), grep for specifics in the middle. This reduces token consumption by 90%+ while maintaining accuracy."

Principle 3: Trust Pre-computed Metrics

"The server analyzes 100% of the source. Use its metrics exactly — never re-count from potentially truncated context."

Principle 4: Zero Fabrication

"Every number, table name, and field name must come from the actual source or SAP system. No guessing, no placeholder data, no estimates."

Principle 5: Deterministic Routing

"PATH A (fill_template_with_values) or PATH B (write_document) — never both. The decision is made by get_document_template based on docx_fill_available."

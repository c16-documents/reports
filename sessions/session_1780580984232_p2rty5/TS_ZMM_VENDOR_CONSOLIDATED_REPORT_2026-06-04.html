PROCESSING LOGIC

High-Level Pseudo Code:

PROGRAM ZMM_VENDOR_CONSOLIDATED_REPORT

1. DECLARE STRUCTURES:
  - ty_final: Main output structure containing all vendor + address + custom fields
  - lt_final: Final output internal table
  - lt_fcat: Field catalog for ALV display

2. SELECTION-SCREEN DEFINITION:
  - Block B1: Input Selection Criteria
  * s_ktokk: Vendor Account Group range
  * s_erdat: Creation Date range
  * s_gvend: Group Vendor range (BUT050)
  * s_lifnr: Vendor Number range
  * p_status: Status listbox (ACTIVE/INACTIVE)
  * p_black: Blacklist listbox (YES/NO)
  * p_begru: Business Relationship Group (YES/NO)
  * p_begru1: Secondary Business Relationship Group (YES/NO)
  * p_brsch: Business Sector (YES/NO)

3. AT SELECTION-SCREEN OUTPUT:
  FOR EACH listbox field (p_status, p_black, p_begru, p_begru1, p_brsch):
  - APPEND value-key and value-text
  - CALL VRM_SET_VALUES to populate listbox

4. START-OF-SELECTION:
  - VALIDATE mutual exclusivity: Only ONE secondary field can be selected
  - If all criteria are INITIAL:
  * SELECT from TVARVC where name = 'ZMM_VEND_ACC_GROUP'
  * Fill s_ktokk with default vendor account groups

5. MAIN DATA FETCH (1st SELECT - LFA1):
  SELECT lifnr, name1, ort01, ktokk, erdat, ernam, sortl, stceg,
  po_nonpovendor, risk_code, risk_catg, telf1, telf2, bahns,
  stcd1, stcd2, stcd3, stcd4, stcd5, brsch, zzeinvoice, begru,
  sperr, sperm, sperq
  FROM lfa1
  FOR ALL ENTRIES IN s_ktokk
  WHERE ktokk EQ s_ktokk-low
  INTO lt_lfa1

6. IF lt_lfa1 IS NOT INITIAL:
  SORT lt_lfa1 BY lifnr

7. 2nd SELECT (CVI_VEND_LINK):
  SELECT vendor, partner_guid FROM cvi_vend_link
  FOR ALL ENTRIES IN lt_lfa1
  WHERE vendor = lt_lfa1-lifnr
  INTO lt_partner_guid
  SORT lt_partner_guid BY vendor

8. 3rd SELECT (BUT000):
  IF lt_partner_guid IS NOT INITIAL:
  SELECT partner_guid, partner FROM but000
  FOR ALL ENTRIES IN lt_partner_guid
  WHERE partner_guid = lt_partner_guid-partner_guid
  INTO lt_partner
  SORT lt_partner BY partner_guid

9. 4th SELECT (BUT050 - GROUP VENDOR):
  IF lt_partner IS NOT INITIAL:
  SELECT partner1, partner2 FROM but050
  FOR ALL ENTRIES IN lt_partner
  WHERE partner1 = lt_partner-partner
  INTO lt_group_vendor

10. 5th-10th SELECTS (ADDRESS + MASTER DATA):
  - ADRC: Address details
  - LFB1: Payment Terms
  - LFM1: Currency
  - ADR6: Email Address
  - ADRCT: Address Text
  - ZVENDOR_BLOCK: Vendor Blacklist Status

11. 11th SELECT (ZMM_VENDOR_MSME):
  SELECT lifnr, msme_cert_num FROM zmm_vendor_msme
  FOR ALL ENTRIES IN lt_lfa1
  WHERE lifnr = lt_lfa1-lifnr
  INTO lt_zmm_vendor_msme

12. 12th SELECT (ZMM_VENDOR_BEE):
  SELECT lifnr, bee_level FROM zmm_vendor_bee
  FOR ALL ENTRIES IN lt_lfa1
  WHERE lifnr = lt_lfa1-lifnr
  INTO lt_zmm_vendor_bee

13. LOOP AT lt_lfa1:
  - MOVE-CORRESPONDING each vendor record to ls_final
  - CHECK vendor deletion status (IF sperr OR sperm OR sperq)
  - READ from lookup tables (partner_guid, zterm, waers, etc.)
  using binary search (READ TABLE ... BINARY SEARCH)
  - Populate full address from concatenated ADRC + ADR6 + ADRCT
  - Read MSME certificate number from ZMM_VENDOR_MSME
  - Read BEE level from ZMM_VENDOR_BEE
  - APPEND ls_final TO lt_final

14. BUILD FIELD CATALOG (SLIS):
  FOR EACH field in ty_final:
  - APPEND to lt_fcat with column label, position, width
  - Set justified, changeable, optimize flags

15. CALL REUSE_ALV_GRID_DISPLAY:
  - Pass lt_final as data table
  - Pass lt_fcat as field catalog
  - EXPORTING is_layout, i_callback_user_command, etc.
  - Display interactive ALV grid

16. END PROGRAM

2. For All Entries (FAE) Multi-Select Logic

Implement FAE pattern with SORT + BINARY SEARCH for optimal performance
Instead of nested LOOP AT, use:
  SORT lt_lookup BY key_field.
  LOOP AT lt_main INTO ls_main.
  READ TABLE lt_lookup INTO ls_lookup
  WITH KEY key_field = ls_main-key_field
  BINARY SEARCH.
  IF sy-subrc = 0.
  ls_main-lookup_field = ls_lookup-lookup_field.
  ENDIF.
  ENDLOOP.

This report is built using standard ABAP syntax compatible with ECC 7.40 and will continue to function after any future SAP support pack upgrades. The following considerations apply:

ASSUMPTIONS IN TECHNICAL DESIGN
  • Vendor master data is maintained in standard SAP tables (LFA1, LFB1, LFM1) and address tables (ADRC, ADR6, ADRCT)
  • Business Partner relationships are configured in BUT000 / BUT050
  • Custom fields (MSME certificate, BEE level, blacklist flag) are stored in dedicated custom tables managed by business users
  • Vendor Account Group variant (ZMM_VEND_ACC_GROUP) is pre-configured in TVARVC if no selection criteria are provided
  • CVI_VEND_LINK table exists and is synchronized for all vendors in LFA1
  • ALV framework REUSE_ALV_GRID_DISPLAY is available in the SAP system (standard delivery)
  • Users have authorization to display vendor data (F_LFA1_BEK with ACTVT=05)
  • Email addresses, phone numbers, and address data are maintained in standard address tables
OPEN ISSUES IN TECHNICAL DESIGN
  • Performance at scale: With >100K vendors, the report may exceed ALV grid row limits. Consider implementing pagination or summary report alternatives.
  • CVI_VEND_LINK availability: If CVI_VEND_LINK is not synchronized, group vendor mapping will fail silently. Add error handling for empty lt_partner_guid.
  • Secondary field mutual exclusivity logic: Current implementation uses complex nested IF statements. Could be simplified with a flag-based approach or dedicated validation subroutine.
  • Custom table dependencies: Report requires three custom tables (ZVENDOR_BLOCK, ZMM_VENDOR_MSME, ZMM_VENDOR_BEE) that must be created prior to deployment. Consider bundling as part of the transport package.
  • Text element management: Hard-coded TEXT-XXX references in field catalog. Consider using dynamic text retrieval (READ TEXTPOOL) for multilingual support.
  • Email validation: No validation of email format from ADR6. Consider adding regex validation before display.
